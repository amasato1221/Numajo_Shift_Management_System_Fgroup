## 1. 前提

- Windows 11 の PC を使います。
- 開発には **Eclipse だけ**を使います（VS Code の使用は禁止）。
- ソフトウェアの版は 10_基本設計書 2.2 の表に合わせます（新井のPCの版）。この手順では、すでに入っているかを確かめ、足りないものだけを入れます。
- コマンドは「Windows PowerShell」で実行します。`>` は入力の目印で、打ちません。

## 2. ソフトウェアの確認

### 2.1 版を確かめる

PowerShell で次を実行し、右の版と同じか確かめます。

| コマンド | 期待する表示 |
| --- | --- |
| `> java -version` | `java version "22.0.1"` |
| `> git --version` | `git version 2.54.…` |
| `> & "C:\Program Files\MySQL\MySQL Server 8.4\bin\mysql.exe" --version` | `Ver 8.4.5` |
| `> Get-Service MySQL84` | `Status` が `Running` |

違う版だったり入っていなかったりしたときは、2.2 で入れます。Maven は入れません（Eclipse 内蔵の Maven と、リポジトリの Maven Wrapper `mvnw.cmd` を使う）。

### 2.2 足りないものを入れる

| ソフトウェア | 入れ方 |
| --- | --- |
| Oracle JDK 22.0.1 | Oracle の Java アーカイブ（Java SE 22）から `jdk-22.0.1_windows-x64_bin.msi` を入れる。入れる場所は既定の `C:\Program Files\Java\jdk-22` |
| Git for Windows 2.54 | 公式サイトから入れる。途中の選択はすべて既定のまま（改行コードは 3章で設定する） |
| MySQL 8.4.5 | MySQL Installer で「Server only」。サービス名 `MySQL84`、ポート 3306、root のパスワードを決めて控える |
| Eclipse 2025-12（Pleiades） | Pleiades All in One の「Java Full Edition」を解凍する。Lombok は Pleiades に入っている（1.18.42） |

### 2.3 環境変数

「設定」→「システム」→「バージョン情報」→「システムの詳細設定」→「環境変数」の「ユーザー環境変数」に次を作ります。作ったあとは、開いている PowerShell と Eclipse を一度閉じて開き直します。

| 名前 | 値 | 使うところ |
| --- | --- | --- |
| `JAVA_HOME` | `C:\Program Files\Java\jdk-22` | `mvnw.cmd` |
| `DB_PASSWORD` | 6.1 で決める `shift_app` のパスワード | アプリとテストの DB 接続（10_基本設計書 8章） |

`DB_PASSWORD` の値はファイルに書いたり、チャットに貼ったりしません（94_セキュリティ設計書 3.10）。

## 3. Git の設定

```powershell
> git config --global user.name "自分の名前（ローマ字）"
> git config --global user.email "GitHub に登録したメールアドレス"
> git config --global core.autocrlf false
> git config --global core.quotepath false
```

- `core.autocrlf false`：改行コードはリポジトリの `.gitattributes` に任せます（92_Git運用規約 1.3）。
- `core.quotepath false`：日本語のファイル名（設計書）が `\346\…` のように表示されないようにします。

リポジトリを取ってきます。場所は Eclipse のワークスペースの中にします（例：`C:\pleiades\2025-12\workspace`）。

```powershell
> cd C:\pleiades\2025-12\workspace
> git clone https://github.com/amasato1221/numajo_shift_management_system_fgroup.git
```

Eclipse を起動し、ワークスペースに 3章の `workspace` フォルダを選びます。「ウィンドウ」→「設定」で次のとおりにします（91_コーディング規約 6章と同じ内容）。

| 2 | Java → コンパイラー | 準拠レベル 22 |
| 3 | 一般 → ワークスペース | テキスト・ファイルのエンコード：UTF-8、新規テキスト・ファイルの行区切り文字：Unix |
| 4 | 一般 → コンテンツ・タイプ → テキスト → Java プロパティー・ファイル | デフォルト・エンコードに `UTF-8` と入れて「更新」 |
| 5 | Java → コード・スタイル → フォーマッター | 「新規」→ 名前 `numajo-fgroup`、元のプロファイル「Eclipse [組み込み]」→ インデント「スペースのみ」、サイズ 4、「行の折り返し」の最大行幅 120 |

## 5. プロジェクトの取り込み

1. 「ファイル」→「インポート」→「Maven」→「既存 Maven プロジェクト」。
2. ルート・ディレクトリーに `numajo_shift_management_system_fgroup` を選び、`pom.xml` にチェックが入っていることを確かめて「完了」。
3. 初回は依存ライブラリのダウンロードに数分かかります。右下の進み具合が終わるまで待ちます。
4. プロジェクトを右クリック →「Maven」→「プロジェクトの更新」→「OK」。
5. 「問題」ビューにエラーが0件であることを確かめます。Lombok のエラー（`getXxx() が未定義`）が出たときは 10章の No.4。

## 6. データベースの準備と初回起動

### 6.1 データベースとユーザーを作る

PowerShell で root としてログインします。

```powershell
> & "C:\Program Files\MySQL\MySQL Server 8.4\bin\mysql.exe" -u root -p
```

次の SQL を実行します。`ここにパスワード` は自分で決めた `shift_app` のパスワードに置き換え、2.3 の `DB_PASSWORD` と同じにします。

```sql
-- 本番用とテスト用のデータベース（40_DB設計書 1章）
CREATE DATABASE shift_management CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE DATABASE shift_test CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;

-- アプリが使うユーザー（同じPCからだけ接続できる）
CREATE USER 'shift_app'@'localhost' IDENTIFIED BY 'ここにパスワード';
GRANT ALL PRIVILEGES ON shift_management.* TO 'shift_app'@'localhost';
GRANT ALL PRIVILEGES ON shift_test.* TO 'shift_app'@'localhost';
-- バックアップ（mysqldump --routines）に必要
GRANT SHOW_ROUTINE ON *.* TO 'shift_app'@'localhost';
FLUSH PRIVILEGES;
EXIT;
```

- テーブルは作りません。アプリの初回起動で Flyway が `V1__create_tables.sql`・`V2__insert_initial_data.sql` を流します（40_DB設計書 7章）。
- タイムゾーンの表（`mysql_tzinfo_to_sql`）は入れなくてかまいません。接続 URL で `+09:00` を指定しているためです（10_基本設計書 8章）。

### 6.2 バックアップの保存先を作る

```powershell
> mkdir C:\shift-management\backup
```

（`app.backup.dir` の値。10_基本設計書 8章）

### 6.3 実行の構成を作る

1. `src/main/java/jp/numajo/fgroup/shift/ShiftManagementApplication.java` を右クリック →「実行」→「実行の構成」。
2. 「Java アプリケーション」を右クリック →「新規構成」。名前 `shift-management`、メイン・クラス `jp.numajo.fgroup.shift.ShiftManagementApplication`。
3. 「環境」タブ →「追加」→ 名前 `DB_PASSWORD`、値は 6.1 のパスワード（2.3 でユーザー環境変数を作っていれば不要）。
4. 「適用」→「実行」。

### 6.4 初回起動で確かめること

**先に読むこと：** 初期管理者のパスワードは誰でも同じなので、変えるまでの間にほかの端末からログインされないようにします。

- 初回起動で Windows のファイアウォールの確認が出ても、下の順4（パスワードの変更）が終わるまでは**許可しない**（「キャンセル」を押す）。スマホから使うための許可は 9.2 で行います。
- 初期管理者のパスワードは新井から聞きます（リポジトリには書いていません。94_セキュリティ設計書 3.10）。
- 起動したら、ほかの作業をする前にすぐ順2〜4を行います。

| 順 | 確かめること | 期待する結果 |
| --- | --- | --- |
| 1 | コンソールのログ | `Successfully applied 2 migrations to schema "shift_management"`、続いて `BT-02 募集期間を0件締め切りました`、`BT-01 募集期間を4件作成しました`、`Tomcat started on port 8080` |
| 2 | ブラウザで `http://localhost:8080/` | ログイン画面（SC-01）が出る |
| 3 | ID `admin`、初期パスワード（新井から聞いたもの）でログイン | パスワード変更画面（SC-03）へ移動する |
| 4 | 新しいパスワードを決めて変更 | 管理メニュー（SA-01）が出る。**この管理者パスワードは控えておく** |
| 5 | MySQL で `SELECT start_date, status FROM shift_management.shift_periods;` | 4行（95_通知・定期処理設計書 2.3 と同じ考え方） |
| 6 | MySQL で `SELECT NOW(), created_at FROM shift_management.operation_logs ORDER BY id DESC LIMIT 1;` | `created_at` が日本時間（9時間ずれていない） |

6 で9時間ずれていたら、起動クラスの `TimeZone.setDefault` と接続 URL を 10_基本設計書 8章・30-01 と見比べます。

## 7. バックアップから戻す

SA-04 で作ったバックアップ（`C:\shift-management\backup\backup_yyyyMMdd_HHmmss.sql`）で、DB を元に戻す手順です。**今の DB の中身はすべて消えて、バックアップの時点に戻ります。** 新井が行います。

1. Eclipse の「停止」ボタン（またはコマンドプロンプトで Ctrl+C）でアプリを止める。
2. 念のため今の状態も残す：SA-04 は使えないので、次のコマンドで手動で取る。
   ```powershell
   > & "C:\Program Files\MySQL\MySQL Server 8.4\bin\mysqldump.exe" -u root -p --single-transaction --routines --no-tablespaces --default-character-set=utf8mb4 --result-file=C:\shift-management\backup\before_restore.sql shift_management
   ```
3. 戻す（PowerShell では `<` が使えないので、コマンドプロンプト `cmd` で実行する）。
   ```bat
   > cd C:\shift-management\backup
   > "C:\Program Files\MySQL\MySQL Server 8.4\bin\mysql.exe" -u root -p --default-character-set=utf8mb4 shift_management < backup_20261020_184012.sql
   ```
4. アプリを起動する。Flyway は `flyway_schema_history` もバックアップから戻っているので、何もしません。
5. 管理者でログインし、SA-03 の操作ログが戻した時点までになっていることを確かめる。

## 8. 管理者のパスワードを忘れたとき

管理者のパスワードを初期化できる画面はありません（94_セキュリティ設計書 2.5）。新井が MySQL で次を実行し、初期パスワード（班の中だけで共有しているもの）に戻します。戻したら、すぐにログインして変えます（6.4 と同じく、変えるまではほかの端末から接続できない状態で行う）。

```sql
UPDATE shift_management.users
   SET password_hash = '$2a$10$nwP/4KBszvToflYP2jG7Xuot0dCbS9iyyW1nUypDuITDqBHfVvub6',
       must_change_password = TRUE,
       failed_login_count = 0,
       locked_until = NULL
 WHERE login_id = 'admin';
```

（ハッシュは 40_DB設計書 7章の V2 と同じ値です。）実行したらすぐにログインし、新しいパスワードに変えます。

## 9. 課題期間中・発表のときの動かし方

### 9.1 実行可能 JAR を作って動かす

```powershell
> cd C:\pleiades\2025-12\workspace\numajo_shift_management_system_fgroup
> .\mvnw.cmd clean package
> java -jar target\shift-management-system-1.0.0-SNAPSHOT.jar
```

- `clean package` ではテストも動きます（テスト用 DB `shift_test` が必要。97_テスト計画書 3章）。
- 止めるときは Ctrl+C。

### 9.2 スマホ・タブレットから使う

1. `ipconfig` で新井のPCの IPv4 アドレス（例：`192.168.1.10`）を調べる。
2. `application.yml` の `app.base-url` をそのアドレスに変える：`--app.base-url=http://192.168.1.10:8080` を `java -jar` の後ろに付けてもよい（ファイルを変えずに済む）。
3. 初回は Windows のファイアウォールの確認が出るので「プライベート ネットワーク」で許可する。6.4 で「キャンセル」を押していて確認が出ないときは、「Windows セキュリティ」→「ファイアウォールとネットワーク保護」→「ファイアウォールによるアプリケーションの許可」で、`java`（JDK 22）の「プライベート」にチェックを入れる。**初期管理者のパスワードを変えた後に行うこと**（6.4）。
4. スマホを同じ Wi-Fi につなぎ、`http://192.168.1.10:8080/` を開く。

### 9.4 外部カレンダーの確認（Google カレンダーの制約）

Google カレンダーの「URL で追加」は、Google のサーバーがアプリに読みに来る方式です。新井のPCはインターネットから届かないため、**課題期間中は Google カレンダーには反映されません**（10_基本設計書 2.1）。確認は次のどちらかで行います。

- 同じ Wi-Fi の iPhone・Mac で、SB-05 の「iPhone・Macで開く」（`webcal://…`）から購読する。
- SB-05 の購読 URL をブラウザで開いて `.ics` を保存し、Google カレンダーの「設定」→「インポート」で読み込む（その時点のシフトが1回だけ入る）。

## 10. うまくいかないとき

| No. | 症状 | 原因と直し方 |
| --- | --- | --- |
| 1 | `Access denied for user 'shift_app'@'localhost'` | `DB_PASSWORD` が違う、または Eclipse を開き直していない。2.3・6.3 を見直す |
| 2 | `Communications link failure` | MySQL が止まっている。`Start-Service MySQL84`（管理者の PowerShell） |
| 3 | `Port 8080 was already in use` | もう1つアプリが動いている。Eclipse のコンソールの赤い「停止」ボタンで止める |
| 4 | Lombok のメソッドがないというエラー | Eclipse を Pleiades の `eclipse.exe` から起動しているか確かめる（`eclipse.ini` に `-javaagent:…lombok.jar` がある）。プロジェクトを「Maven」→「プロジェクトの更新」 |
| 5 | 画面のメッセージが `??E1303_ja??` や文字化け | 4章の 4（プロパティー・ファイルのエンコード）。`messages.properties` を開き直して UTF-8 で保存し直す |
| 6 | 時刻が9時間ずれる、`Check constraint …_chk_1 is violated` で時刻が入らない | 接続 URL の `connectionTimeZone=%2B09:00&forceConnectionTimeZoneToSession=true` と起動クラスの `TimeZone.setDefault` を確かめる（30-01） |
| 7 | `Validate failed: Migrations have failed validation` | `V1`・`V2` の SQL を書き換えた。適用済みの SQL は変えず、直したいときは `V3__…sql` を足す（40_DB設計書 7章）。開発中にやり直したいときだけ `DROP DATABASE shift_management; CREATE DATABASE …`（6.1）で作り直す |
| 8 | バックアップが失敗する（E4401） | `app.backup.mysqldump-path` のパス、`C:\shift-management\backup` があるか、6.1 の `SHOW_ROUTINE` の権限 |
| 9 | `mvnw.cmd` で `JAVA_HOME` のエラー | 2.3 の `JAVA_HOME` を作り、PowerShell を開き直す |
