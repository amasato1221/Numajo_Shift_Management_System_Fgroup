## 1. 画面の流れ

画面は1つで、GET のパラメーターによって「① 日付と人を選ぶ」「② 内容を確かめて登録する」の2段階を出し分けます。JavaScript（Ajax）は使いません。

| パラメーター | 表示 |
| --- | --- |
| どちらもない | ① 日付＝今日 |
| `date` だけ | ① その日付 |
| `assignmentId` あり | ② その割当（`date` は無視し、割当の日付を使う） |

SM-01 の「欠勤を登録」ボタンは `/manager/absences`、SM-06 の「欠勤」リンクは `/manager/absences?assignmentId={id}` を開きます。

## 2. 画面項目

### 2.1 ① 日付と人を選ぶ

| No. | 項目 | 種類 | name／表示元 | 内容 |
| --- | --- | --- | --- | --- |
| 1 | 日付 | `<input type="date">`（GETフォーム、自動送信 `data-auto-submit`） | `date` | `min` は今日。初期値は今日 |
| 2 | その日の出勤者 | 表 | `candidatesOfDay`（`List<AbsenceTargetRow>`） | **公開済みの期間**の、その日の ASSIGNED の割当。並びは開始時刻→ふりがな。列：枠（☀日勤／☾夕勤／時間指定 13:00〜22:00）、氏名、操作「この人を欠勤にする」（リンク `/manager/absences?assignmentId={id}`） |
| 3 | すでに欠勤の人 | 表 | `absentsOfDay` | 同じ日の ABSENT の割当。列：枠、氏名、登録日時、通知日時。操作なし |
| 4 | 0件 | テキスト | － | 出勤者がいない：I2701「この日に公開済みのシフトはありません。」 |

## 3. 処理

### 3.1 ① の表示（GET /manager/absences、`assignmentId` なし）

1. `date` が null・形式違い → 今日。今日より前 →【エラー】E2702 を errorMessage に入れ、今日で表示する。
2. `AbsenceService#getDay(date)`：
   1. `ShiftAssignmentRepository#findPublishedByWorkDate(date)`：
      ```java
      @Query("""
          SELECT a FROM ShiftAssignment a JOIN FETCH a.user u LEFT JOIN FETCH a.slot
          WHERE a.workDate = :date AND a.period.status = jp.numajo.fgroup.shift.constant.PeriodStatus.PUBLISHED
          ORDER BY a.startTime ASC, u.nameKana ASC NULLS LAST, u.id ASC
          """)
      List<ShiftAssignment> findPublishedByWorkDate(@Param("date") LocalDate date);
      ```
   2. status で ASSIGNED（No.2）と ABSENT（No.3）に分ける。ABSENT の行には `absences` の `created_at` と `notified_at` を付ける（`AbsenceRepository#findByAssignmentIdIn`）。
3. model：`date`、`candidatesOfDay`、`absentsOfDay`。`manager/absence` を返す。

> No.3 の「通知した人数」は保存していないため出しません。「通知済み（yyyy/MM/dd HH:mm）」と `notified_at` だけを出します。

### 3.2 ② の表示（GET /manager/absences?assignmentId={id}）

1. `AbsenceService#getConfirm(assignmentId)`：
   1. 割当がない → 404。
   2. 3.3 の 2-2〜2-4 のチェックをして、だめなら【エラー】（フラッシュ errorMessage で `redirect:/manager/absences?date={割当の日付}`）。
   3. 通知する相手：3.4 の `findVacancyRecipients(assignment)`。
   4. 既定の通知文：`messageSource.getMessage("I2702", {M, d, 枠名})`＝「{0}月{1}日の{2}に1人欠員が出ました。入れる方は店舗に連絡してください。」。枠名は日勤／夕勤、時間指定なら「13:00〜22:00」。
2. model：`target`、`recipients`、`absenceForm`（`assignmentId`・`noticeMessage` に値を入れたもの）。

### 3.3 登録（POST /manager/absences）

1. 入力チェック。エラー → 3.2 の値を入れ直し、送られたフォームのまま再表示。
2. `AbsenceService#register(assignmentId, reason, noticeMessage, operatorId)`（`@Transactional`）。次の順にチェック：
   1. 割当がない → 404。
   2. 期間が PUBLISHED でない →【エラー】E2706
   3. 割当の status が ABSENT →【エラー】E2707
   4. 割当の日付が今日より前 →【エラー】E2702
3. 保存：
   1. 割当の status を ABSENT にする。
   2. `absences` に1行：`assignment_id`、`registered_by`＝店長、`reason`、`notice_message`、`notified_at`＝今。
   3. 通知する相手（3.4）それぞれに VACANCY のお知らせ：件名 N0004（引数：`M月d日`、枠名）、本文＝`noticeMessage`、link_url `/staff/home`。
   4. 欠勤した本人に CHANGED のお知らせ：件名 N0003、本文 N1005「{M月d日(E)} {枠名} が欠勤になりました。」（時間指定なら枠名に N1006）、link_url `/staff/shifts?periodId={期間ID}`。
   5. 操作ログ `ABSENCE_REGISTER`（target：`assignment:{id}`、detail：`user={userId} date={yyyy-MM-dd} slot={DAY/EVENING/TIME} recipients={人数}`）。
   6. 通知した人数を返す。
4. `redirect:/manager/periods/{期間ID}`、フラッシュ I2703（引数：人数）。人数が0なら warningMessage に W2701 も入れる。
5. 業務エラー → フラッシュ errorMessage で `redirect:/manager/absences?date={割当の日付}`。

**登録は取り消せません**（01_仕様書の範囲外）。間違えたときは、SM-06 の「時間指定で割り当てる」で同じ時刻に割り当て直します（欠勤の割当は重なりの判定に入らないため割り当てられる）。

### 3.4 通知する相手（AbsenceService#findVacancyRecipients）

```
対象の枠 S = 割当に slot_id があればその枠だけ
            なければ、割当の時間と重なる枠すべて（ShiftTimeUtil#overlaps）
必要な職能 K = S の各枠の必要職能をすべて合わせたもの
相手 = 有効な（is_active = TRUE）バイト（role = STAFF）のうち
       ・欠勤する本人ではない
       ・職能に K をすべて含む（K が空なら全員が当てはまる）
       ・その日に、割当の時間と重なる ASSIGNED の割当がない
       （研修中の人も含む）
並び：ふりがな昇順（null は最後）、同じなら id 昇順
```

SQLは「有効なバイトと職能」（`UserRepository#findActiveStaffWithSkills()`）と「その日の ASSIGNED の割当」（`ShiftAssignmentRepository#findByWorkDateAndStatus(date, ASSIGNED)`）の2回だけにし、条件の判定は Java で行います。

## 7. テストの観点

| No. | 観点 | 期待結果 |
| --- | --- | --- |
| 1 | 今日を開く | 公開済みの期間の今日の出勤者だけ出る（作成中の期間の割当は出ない） |
| 2 | 昨日の日付を送る | E2702、今日で表示 |
| 3 | 日勤の人を欠勤にする | 割当が ABSENT、absences が1行、本人に CHANGED、相手に VACANCY、操作ログ |
| 4 | 日勤にレジが必須 | レジのない人は相手に入らない |
| 5 | 同じ日の夕勤に入っている人 | 相手に入る（時間が重ならない） |
| 6 | 同じ日の 13:00〜22:00 に入っている人 | 相手に入らない |
| 7 | 時間指定 13:00〜22:00 の人が欠勤 | 日勤と夕勤の両方の必要職能を持つ人だけが相手 |
| 8 | 研修中の人 | 相手に入る |
| 9 | 無効なバイト | 相手に入らない |
| 10 | 相手が0人 | 登録はでき、W2701 |
| 11 | もう一度同じ割当を登録（二重送信） | E2707 |
| 12 | 作成中の期間の割当IDを送る（改ざん） | E2706 |
| 13 | 通知する文を空・501文字 | E2704・E2705 |
| 14 | 欠勤後の SM-06 | セルが「欠」、人数不足の警告が出る |
