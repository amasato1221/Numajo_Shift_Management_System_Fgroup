## 1. 画面項目

| No. | 項目 | 種類 | name | 入力チェック（フォーム） | 備考 |
| --- | --- | --- | --- | --- | --- |
| 1 | 初回のお願い | アラート（黄） | － | － | `loginUser.mustChangePassword` が true のときだけ W0301 |
| 2 | ログインID | 表示 | `loginUser.loginId` | － | 変更不可 |
| 3 | 今のパスワード | password | `currentPassword` | `@NotBlank(E0301)` | `autocomplete="current-password"` |
| 4 | 新しいパスワード | password | `newPassword` | `@NotBlank(E0302)`、`@Pattern(regexp="^[\\x21-\\x7E]{8,64}$", E0303)` | 下に「半角の英字・数字・記号で8〜64文字」と表示 |
| 5 | 新しいパスワード（確認） | password | `confirmPassword` | `@NotBlank(E0304)` | |
| 6 | 変更する | ボタン | － | － | `btn btn-success` |

- 入力チェックでエラーになったときは、3〜5の入力欄を空にして再表示します（パスワードを画面に戻さない）。

## 2. 処理

### 2.1 初期表示（GET /account/password）

1. `model.addAttribute("passwordChangeForm", new PasswordChangeForm())`。
2. `common/account-password` を返す。

### 2.2 変更（POST /account/password）

1. 入力チェック（`@Validated`）。エラー → フォームの3つの値を null にして画面を再表示。
2. `UserService#changePassword(userId, currentPassword, newPassword, confirmPassword)`
   1. `newPassword` と `confirmPassword` が違う →【エラー】E0305
   2. ユーザーを取得し、`passwordEncoder.matches(currentPassword, passwordHash)` が false →【エラー】E0306
   3. `passwordEncoder.matches(newPassword, passwordHash)` が true（今と同じ）→【エラー】E0307
   4. `password_hash = passwordEncoder.encode(newPassword)`、`must_change_password = FALSE`。
   5. 操作ログ `PASSWORD_CHANGE`。
3. セッションの `LoginUser#passwordChanged()` を呼ぶ（以降、ほかの画面を開けるようになる）。
4. `redirect:` ＋ `HomeUrl.of(role)`、フラッシュ I0301。
5. 業務エラーのとき → フラッシュ errorMessage、`redirect:/account/password`。

## 5. 操作ログ

PASSWORD_CHANGE

## 6. テストの観点

| No. | 観点 | 期待結果 |
| --- | --- | --- |
| 1 | 3項目とも空 | E0301・E0302・E0304 |
| 2 | 新しいパスワードが7文字／8文字／64文字／65文字 | E0303／OK／OK／E0303 |
| 3 | 全角文字・空白を含む | E0303 |
| 4 | 確認が違う | E0305、DBは変わらない |
| 5 | 今のパスワードが違う | E0306 |
| 6 | 今と同じパスワード | E0307 |
| 7 | 正しく変更（初回） | ホームへ、must_change_password が FALSE、ほかの画面を開ける |
| 8 | 変更後に新しいパスワードでログイン | ログインできる、古いパスワードではできない |
