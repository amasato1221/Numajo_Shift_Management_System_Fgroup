## 2. 処理

### 2.1 初期表示（GET /admin/backups）

1. `BackupService#findRecent(50)`：`BackupRepository#findLatest50()`。
2. model：`backups`、`backupDir`。`admin/backups` を返す。

### 2.2 作成（POST /admin/backups）

1. `BackupService#create(adminUserId)`（このメソッド自体は `@Transactional` にしない。DBへの記録は最後に別に行う）
   1. 同時に2つ動かさない：`AtomicBoolean running` が true →【エラー】E4402。`compareAndSet(false, true)` で取り、最後に `finally` で false に戻す。
   2. ファイル名：`backup_` ＋ 今を `yyyyMMdd_HHmmss` にしたもの ＋ `.sql`（例：`backup_20261020_184012.sql`）。
   3. 保存先フォルダ（`app.backup.dir`）がない → `Files.createDirectories` で作る。作れない → 失敗として 6 へ。
   4. 接続先：`spring.datasource.url` から ホスト・ポート・DB名を取り出す（`jdbc:mysql://{host}:{port}/{db}?...` を `URI.create(url.substring(5))` で分ける）。ユーザー名は `spring.datasource.username`。
   5. コマンドを実行する。`ProcessBuilder` は直接使わず、包んだクラス `ProcessRunner` を使う（テストでモックにするため）。**文字列をつなげて1本のコマンドにしない**。引数はリストで渡す。
      ```java
      List<String> command = List.of(
          props.getBackup().getMysqldumpPath(),
          "--host=" + host, "--port=" + port, "--user=" + username,
          "--single-transaction", "--routines", "--no-tablespaces",
          "--default-character-set=utf8mb4",
          "--result-file=" + file.toAbsolutePath(),
          dbName);
      // パスワードはコマンドの引数に入れず、環境変数 MYSQL_PWD で渡す
      ProcessResult result = processRunner.run(command, Map.of("MYSQL_PWD", dataSourcePassword),
              Duration.ofSeconds(props.getBackup().getTimeoutSeconds()));
      ```
      `ProcessRunner#run` の中身（30_クラス設計書）：`ProcessBuilder` に環境変数を足し、`redirectErrorStream(true)` で起動する。出力は `CompletableFuture.supplyAsync` で別スレッドで読み、`waitFor(timeout)` で待つ。時間切れなら `destroyForcibly()` して `ProcessResult(timedOut=true, exitCode=-1, output)` を返す。
   6. 結果：
      - 成功＝終了コード 0 かつ ファイルの大きさ > 0。
      - 失敗＝それ以外。途中までのファイルがあれば消す（`Files.deleteIfExists`）。出力の先頭200文字をログファイル（`log.warn`）に出す（画面には出さない）。
   7. 記録（`BackupRecorder#record`、`@Transactional(propagation = REQUIRES_NEW)`）：`backups` に1行（`file_name`、`file_size`（失敗なら NULL）、`status`、`created_by`）。操作ログ `BACKUP_CREATE`（target：`backup:{id}`、detail：`file={ファイル名} status={SUCCESS/FAILED}`）。
   8. 結果（`BackupResult(status, fileName)`）を返す。
2. 成功 → フラッシュ I4402（引数：ファイル名）。失敗 → フラッシュ errorMessage＝E4401。`redirect:/admin/backups`。

**自動のバックアップ：** 01_仕様書では「管理者が押したとき」だけなので、定期処理では作りません。

## 6. テストの観点

| No. | 観点 | 期待結果 |
| --- | --- | --- |
| 1 | 正しい設定で作成 | ファイルができ、SUCCESS、大きさが入る、操作ログ |
| 2 | mysqldump のパスが間違い | FAILED、ファイルは残らない、E4401 |
| 3 | DBのパスワードが間違い | FAILED（終了コード 0 以外） |
| 4 | 保存先フォルダがない | 作られて成功 |
| 5 | 2回すばやく押す | 2回目は E4402（または画面で押せない） |
| 6 | タイムアウト（設定を1秒にして大きなDB） | FAILED、プロセスが残らない |
| 7 | 作ったファイルで復元 | 同じデータに戻る（96_環境構築手順書 7章の手順） |
| 8 | 操作ログ・ログファイル | パスワードが出ていない |

テストの No.2〜No.6 は `BackupService` の単体テストで、`ProcessRunner`（`ProcessBuilder` を包んだクラス）をモックにして行います。
