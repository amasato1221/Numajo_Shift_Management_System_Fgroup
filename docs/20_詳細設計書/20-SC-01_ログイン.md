## 2. 処理

### 2.1 初期表示（GET /login）

1. すでにログインしている場合（`Authentication` が匿名でない）→ `redirect:` ＋ `HomeUrl.of(role)`。
2. それ以外は `common/login` を返す。

### 2.2 ログイン（POST /login）

Spring Security の `formLogin` が処理します（94_セキュリティ設計書 2章）。実装するのは次の部品です。

1. `LoginUserDetailsService#loadUserByUsername(loginId)`：`users` をログインIDで探し、`LoginUser` を返す。なければ `UsernameNotFoundException`。
2. Spring Security が次の順で確認する。
   1. ロック中（`locked_until` が今より後）→ `LockedException`
   2. 無効（`is_active = FALSE`）→ `DisabledException`
   3. パスワード（BCrypt）が違う、またはIDがない → `BadCredentialsException`
3. 成功 → `LoginSuccessHandler`
   1. `LoginAttemptService#loginSucceeded(loginId)`：`failed_login_count = 0`、`locked_until = NULL`。
   2. `OperationLogService#recordInNewTransaction(userId, LOGIN_SUCCESS, null, null)`（ログイン処理はトランザクションの外なので、新しいトランザクションで入れる）。
   3. `must_change_password` が TRUE → `/account/password`、FALSE → `HomeUrl.of(role)` へリダイレクト。
4. 失敗 → `LoginFailureHandler`
   1. `BadCredentialsException` でIDが入力されている → `LoginAttemptService#loginFailed(loginId, now)`。
      - 失敗回数＋1。5回目なら `locked_until = now + 15分`、`failed_login_count = 0` にして「ロックした」を返す。
      - IDが存在しないときは何もしない。
   2. 操作ログ：今回の失敗でロックしたら（1 で「ロックした」が返ったら）`LOGIN_LOCKED`、それ以外は `LOGIN_FAILURE`。ロック中にログインを試みた（`LockedException`）ときも `LOGIN_FAILURE` です（SA-03 で「アカウントのロック」が実際にロックした回数だけ出るようにするため）。対象（target）に入力されたログインID、ユーザーが見つかれば user_id も入れる。
   3. ロックした、または `LockedException` → `/login?locked`。それ以外（`DisabledException` を含む）→ `/login?error`。
      - 無効なアカウントも「IDまたはパスワードが違います」にする（アカウントの有無を教えないため）。

### 2.3 ログアウト（POST /logout）

1. どの画面にもあるヘッダーの「ログアウト」ボタン（`<form th:action="@{/logout}" method="post">`）。
2. `LogoutOperationLogHandler` が `LOGOUT` を記録する。
3. セッションを破棄し、`/login?logout` へ。

### 2.4 セッション切れ

- 30分操作がないとセッションが切れる。切れたあとに画面を開くと Spring Security が `/login` に戻す。
- `/login?expired` は、`SecurityConfig` の `sessionManagement().invalidSessionUrl("/login?expired")` で出す。

## 3. 使うクラスとメソッド

| クラス | メソッド |
| --- | --- |
| `LoginController` | `String login(Authentication authentication)` |
| `LoginUserDetailsService` | `UserDetails loadUserByUsername(String loginId)` |
| `LoginAttemptService` | `void loginSucceeded(String loginId)`、`boolean loginFailed(String loginId, LocalDateTime now)` |
| `LoginSuccessHandler` | `void onAuthenticationSuccess(...)` |
| `LoginFailureHandler` | `void onAuthenticationFailure(...)` |
| `LogoutOperationLogHandler` | `void logout(...)` |
| `OperationLogService` | `void recordInNewTransaction(Long userId, OperationAction action, String target, String detail)`（ログインの処理はトランザクションの外なので、新しいトランザクションで記録する。30-04 5章） |

## 4. メッセージ

E0101、E0102、I0101、W0101、W0102（93_メッセージ一覧）

## 5. 操作ログ

LOGIN_SUCCESS、LOGIN_FAILURE、LOGIN_LOCKED、LOGOUT

## 6. テストの観点

| No. | 観点 | 期待結果 |
| --- | --- | --- |
| 1 | 正しいID・パスワード（初回） | `/account/password` へ |
| 2 | 正しいID・パスワード（変更済み）バイト／店長／管理者 | それぞれ SB-01／SM-01／SA-01 へ |
| 3 | パスワード誤り1〜4回目 | `/login?error`、失敗回数が1ずつ増える |
| 4 | パスワード誤り5回目 | `/login?locked`、`locked_until` が15分後、失敗回数0 |
| 5 | ロック中に正しいパスワード | `/login?locked` |
| 6 | ロックから15分たったあと | ログインできる |
| 7 | 存在しないID | `/login?error`、DBは変わらない |
| 8 | 無効なアカウント | `/login?error` |
| 9 | ログイン済みで `/login` を開く | ホームへ |
| 10 | ログアウト | `/login?logout`、I0101、操作ログ LOGOUT |
| 11 | 4回失敗→成功→1回失敗 | 失敗回数は1（成功で0に戻る） |
