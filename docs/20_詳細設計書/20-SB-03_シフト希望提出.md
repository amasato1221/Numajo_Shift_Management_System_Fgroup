## 1. フォームの形

```java
public class ShiftRequestForm {
    @NotNull(message = "{E1301}")
    private Long periodId;
    @Valid
    @NotEmpty(message = "{E1302}")
    private List<DayRequestForm> days = new ArrayList<>();
}

public class DayRequestForm {
    @NotNull(message = "{E1302}")
    private LocalDate workDate;          // hidden
    @NotNull(message = "{E1302}")
    private RequestMode mode;            // SLOT（枠ごとに○×）／TIME（時間指定）
    private Availability dayShift;       // 日勤：OK／NG／null（職能なし・未選択）
    private Availability eveningShift;   // 夕勤：OK／NG／null
    @DateTimeFormat(pattern = "HH:mm")
    private LocalTime startTime;         // 時間指定の開始
    @DateTimeFormat(pattern = "HH:mm")
    private LocalTime endTime;           // 時間指定の終了
}
```

- `RequestMode` は `constant` パッケージの列挙型（SLOT、TIME）。
- `dayShift`・`eveningShift` には `Availability.TIME` を入れない（入っていたら E1302）。
- HTMLの name は `days[0].workDate`、`days[0].mode`、`days[0].dayShift`… の形（`th:field="*{days[__${stat.index}__].dayShift}"`）。

**mode の送り方：** 1日ごとにラジオボタン（SLOT／TIME）で送るので、JavaScriptが動かなくても値は正しく届きます。JavaScriptは表示の切り替えだけを行います。

## 3. 処理

### 3.1 初期表示（GET /staff/requests）

1. `ShiftRequestService#getRequestPage(userId, periodId)` で `RequestPageView` を作る。
   1. 表示する期間：
      - `periodId` あり → その期間。存在しなければ 404。
      - `periodId` なし → OPEN で `deadline_at >= now` の期間のうち期限が一番早いもの。なければ `page = null`。
   2. `editable` ＝ `status == OPEN` かつ `now <= deadline_at`。
   3. 職能：`ShiftRequestService#qualifiedSlotIds(userId)`＝ユーザーの職能が、枠の必要職能を**すべて**含む枠のID（必要職能がない枠は誰でも可）。
   4. 期間の日ごとに `RequestDayRow(workDate, dayQualified, eveningQualified)` を作る。
   5. フォームの初期値：その期間・ユーザーの `shift_requests` から作る。
      - TIME の行がある日 → mode＝TIME、startTime・endTime をセット。
      - それ以外 → mode＝SLOT、`slot_id=1` の行の availability を dayShift、`slot_id=2` を eveningShift（行がなければ null）。
   6. 提出状況：`request_submissions` の `submitted_at`（なければ未提出）。
2. `page = null` のとき：I1301「受付中の期間はありません。」を出し、表は出さない。
3. model：`page`、`shiftRequestForm`、`timeOptions`（`ShiftTimeUtil#timeOptions()`）。`staff/requests` を返す。

### 3.2 提出（POST /staff/requests）

1. 入力チェック（`@Validated`）。エラー → 3.1 と同じ値を入れ直し、送られたフォームのまま再表示。
2. `ShiftRequestService#submit(userId, form)`（`@Transactional`）。次の順にチェックし、最初に見つかったエラーで止める。
   1. 期間がない → 404。
   2. `editable` でない →【エラー】E1303
   3. `days` の日付が、期間の全日付とちょうど一致しない（足りない・多い・重複）→【エラー】E1302
   4. 日ごとのチェック（日付の早い順）：
      - mode＝SLOT：
        - 職能のある枠で値が null →【エラー】E1304（引数：`M月d日`、枠名）
        - 職能のない枠で値が null 以外 →【エラー】E1302
      - mode＝TIME：
        - startTime・endTime のどちらかが null →【エラー】E1305（引数：`M月d日`）
        - 8:00 より前・22:00 より後・分が 0 と 30 以外 →【エラー】E1306（引数：`M月d日`）
        - startTime ≧ endTime →【エラー】E1307（引数：`M月d日`）
        - 職能のない枠と時間が重なる（`start < 枠の終了 && 枠の開始 < end`）→【エラー】E1308（引数：`M月d日`、枠名）
3. 保存：
   1. `ShiftRequestRepository#deleteByPeriodIdAndUserId(periodId, userId)`
   2. 日ごとに `shift_requests` を作る。
      - SLOT：職能のある枠ごとに1行（`slot_id`、`availability`＝OK／NG、時刻は null）。
      - TIME：1行（`slot_id`＝null、`availability`＝TIME、`start_time`、`end_time`）。
   3. `request_submissions` を `(periodId, userId)` で探し、あれば `submitted_at` を今に、なければ作る。
4. `redirect:/staff/requests?periodId={id}`、フラッシュ I1302。
5. 業務エラー → フラッシュ errorMessage／errorArgs、`redirect:/staff/requests?periodId={id}`（入力内容は保存されないため、画面はDBの内容に戻る）。

### 3.3 提出の取り消し（POST /staff/requests/cancel）

1. パラメーター `periodId`（hidden）。
2. `ShiftRequestService#cancel(userId, periodId)`：
   1. 期間がない → 404。`editable` でない →【エラー】E1303
   2. `shift_requests` と `request_submissions` のその期間・ユーザーの行を削除。
3. `redirect:/staff/requests?periodId={id}`、フラッシュ I1303。

## 4. JavaScript（app.js）の動き

| 動き | 対象 | 内容 |
| --- | --- | --- |
| 全部○／全部× | `[data-fill="OK"]`／`[data-fill="NG"]` | mode が SLOT の日の、`disabled` でない OK（NG）のラジオをすべてチェック |
| 入れ方の切替 | `.js-mode-radio` | TIME を選んだ日：プルダウンを表示し、○×のラジオを `disabled`。SLOT を選んだ日：プルダウンを隠し、○×のラジオを使えるようにする |
| 初期表示 | － | mode が TIME の日は、TIME を選んだ状態・プルダウン表示で描画する（サーバー側の Thymeleaf で出し分け、JSに頼らない） |

## 8. テストの観点

| No. | 観点 | 期待結果 |
| --- | --- | --- |
| 1 | 全日・全枠に○×を付けて提出 | 枠ごとに行ができる、提出済みになる |
| 2 | 1か所だけ未選択 | E1304（その日付と枠名） |
| 3 | 職能のない夕勤に OK を送る（改ざん） | E1302 |
| 4 | 時間指定 13:00-22:00（両方の職能あり） | TIME の1行だけ。同じ日の枠の行はない |
| 5 | 時間指定 7:30／22:30／13:15 | E1306 |
| 6 | 時間指定 13:00-13:00、22:00-8:00 | E1307 |
| 7 | 夕勤の職能なしで 13:00-17:00／13:00-17:30 | OK（境界は重ならない）／E1308 |
| 8 | 期限の 23:59:59 ちょうど／翌 0:00:00 | 受け付ける／E1303 |
| 9 | 日付が1日足りない・重複・期間外 | E1302 |
| 10 | 再提出 | 前の行が全部消えて入れ直し、submitted_at が更新 |
| 11 | 取り消し | 行と提出状況が消え、未提出になる |
| 12 | 期限後の取り消し | E1303 |
| 13 | 他人の periodId は関係ない（自分の行だけが変わる） | 他人の希望は変わらない |
| 14 | 受付中の期間がない | I1301 |
