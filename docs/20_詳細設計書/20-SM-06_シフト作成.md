### 2.1 割当表

**行：** 有効なバイト全員と、この期間に希望か割当がある無効なバイト。並びは `name_kana` 昇順、同じなら `id` 昇順。

| 部分 | 表示 |
| --- | --- |
| 行の見出し | 氏名、研修中なら「研」バッジ（黄）、未提出なら「未提出」バッジ（灰）。期間が OPEN か CLOSED なら下に「希望を直す」リンク（SM-06-1） |
| 列の見出し | 上段：日付「11/1(日)」（土曜は青、日曜は赤）。下段：☀・☾ |
| セルの左（希望） | ○（OK）、×（NG）、時（TIME の時間がこの枠と重なる。`title` に「13:00-22:00」）、・（未提出、灰）、－（この枠の職能がない、灰） |
| セルの右（割当） | ●（この枠の割当、出勤）、◐（時間指定の割当がこの枠と重なる、出勤）、欠（この枠の割当が欠勤、赤）。何もなければ空 |
| セルの背景 | 割当（●・◐）があれば薄い緑 |
| 最下行 | 「割当数/必要数」。不足は赤字、研修中のみは黄の背景、足りていれば緑字 |
| 公開済みで ● のセル | 右下に小さな「欠勤」リンク（`/manager/absences?assignmentId={id}`） |

**セルのボタン：** 表全体を1つのフォーム（POST `/manager/periods/{id}/assignments/toggle`）で囲み、各セルを `<button type="submit" name="cell" th:value="|${userId}:${date}:${slotId}|">` にします。`editable` が false のときは `disabled`。

| セルの状態 | ボタンに付ける確認（`data-confirm`） |
| --- | --- |
| ● があり、公開済み | C2604（外すとお知らせが届く） |
| ● があり、作成中 | なし |
| ● がなく、希望が × か未提出 | C2602 |
| ● がなく、職能がない | C2603 |
| 欠 | ボタンを `disabled`（欠勤は変更できない） |
| ◐ だけ | ボタンを `disabled`（時間指定の割当は 10 の表で外す） |

**画面の大きさ：** 16日×2枠＝32列。PCでは表を横スクロール（`.table-responsive`）にし、行の見出しを `position: sticky; left: 0` で固定します。スマホでは「PCで操作してください」（I2604）を出し、表は横スクロールで見るだけにします。

## 3. 処理

### 3.1 期間を選ばずに開いた（GET /manager/periods）

1. `PeriodService#defaultPeriodForManager()`：
   1. CLOSED の期間のうち `start_date` が一番早いもの。
   2. なければ OPEN の期間のうち `start_date` が一番早いもの。
   3. なければ今日を含む期間。
   4. それもなければ I2605 を出して `redirect:/manager/home`。
2. `redirect:/manager/periods/{id}`。

### 3.2 初期表示（GET /manager/periods/{id}）

1. 期間がない → 404。
2. `AssignmentService#getPeriodPage(periodId)` で `PeriodPageView` を作る（SQLは期間ごとに次の6回で済ませる）。
   1. スタッフ：`UserRepository#findStaffForPeriod(periodId)`（有効なバイト＋この期間に希望か割当がある人、職能も一緒に取る）。
   2. 希望：`ShiftRequestRepository#findByPeriodId(periodId)`。
   3. 提出：`RequestSubmissionRepository#findUserIdsByPeriodId(periodId)`。
   4. 割当：`ShiftAssignmentRepository#findByPeriodIdWithUser(periodId)`（ASSIGNED と ABSENT の両方）。
   5. 枠と必要職能：`SlotRepository#findAllWithRequiredSkills()`。
   6. 必要人数：`RequiredStaffService#requiredCounts(start_date, end_date)`。
   7. 警告：`ShiftWarningService#calculate(...)`（取ってきた値を渡して計算だけする版 `calculate(period, slots, assignments, requiredCounts, today)` を使う）。
   8. `editable` ＝ status が CLOSED か PUBLISHED。`publishable` ＝ status が CLOSED かつ TRAINEE_ONLY の警告が0件。
3. model：`page`、`timeAssignmentForm`（空）、`timeOptions`、`staffOptions`（有効なバイト）。`manager/period` を返す。

### 3.3 セルの割当の切替（POST /manager/periods/{id}/assignments/toggle）

1. `cell` を `^(\d+):(\d{4}-\d{2}-\d{2}):([12])$` で分ける。合わない →【エラー】E2601
2. `AssignmentService#toggleSlot(periodId, userId, workDate, slotId, operatorId)`（`@Transactional`）
   1. 期間がない → 404。status が CLOSED・PUBLISHED 以外 →【エラー】E2602
   2. `workDate` が期間外 →【エラー】E2601
   3. ユーザーがない・STAFF でない → 404。
   4. `ShiftAssignmentRepository#findCell(periodId, userId, workDate, slotId)` で探す。
   5. **あるとき（外す）**
      1. status が ABSENT →【エラー】E2603
      2. 削除する。
      3. 期間が PUBLISHED → `NotificationService#notifyChanged(user, period, 本文＝N1004「{M月d日(E)} {枠名} が外れました。」)`。
      4. 操作ログ `ASSIGNMENT_REMOVE`（target：`assignment:{id}`、detail：`user={userId} date={yyyy-MM-dd} slot={DAY/EVENING}`）。
   6. **ないとき（付ける）**
      1. ユーザーが無効 →【エラー】E2604
      2. 同じ人・同じ日に、時間が重なる ASSIGNED の割当がある →【エラー】E2605（引数：氏名、M月d日）
      3. 1行追加：`slot_id`＝slotId、`start_time`・`end_time`＝枠の時刻、status＝ASSIGNED。
      4. 期間が PUBLISHED → お知らせ（`notifyChanged`、本文＝N1003「{M月d日(E)} {枠名} が追加されました。」）。
      5. 操作ログ `ASSIGNMENT_ADD`（target：`assignment:{id}`、detail：`user={userId} date={yyyy-MM-dd} slot={DAY/EVENING}`）。
3. `redirect:/manager/periods/{id}`（業務エラーはフラッシュ errorMessage）。成功のメッセージは出さない（表の変化でわかるため）。

### 3.4 時間指定の割当（POST /manager/periods/{id}/assignments/time）

1. `TimeAssignmentForm`：`userId`（`@NotNull` E2606）、`workDate`（`@NotNull` E2606）、`startTime`・`endTime`（`@NotNull` E2607）。エラー → フラッシュ errorMessage でリダイレクト。
2. `AssignmentService#assignTime(periodId, userId, workDate, startTime, endTime, operatorId)`
   1. 3.3 の 2-1〜2-3 と同じチェック。ユーザーが無効 → E2604。
   2. 時刻が 8:00〜22:00・30分単位でない →【エラー】E2608。開始 ≧ 終了 →【エラー】E2609
   3. 重なる ASSIGNED の割当がある →【エラー】E2605
   4. 1行追加：`slot_id`＝NULL、時刻＝入力値、status＝ASSIGNED。
   5. 公開済みならお知らせ（本文＝N1003。{1} の枠名に N1006「時間指定 {H:mm}〜{H:mm}」を入れる）。操作ログ `ASSIGNMENT_ADD`（target：`assignment:{id}`、detail：`user={userId} date={yyyy-MM-dd} slot=TIME {H:mm}-{H:mm}`）。
3. `redirect:/manager/periods/{id}`、フラッシュ I2606。

### 3.5 割当を外す（POST /manager/periods/{id}/assignments/{assignmentId}/delete）

1. `AssignmentService#delete(periodId, assignmentId, operatorId)`
   1. 割当がない・期間が違う → 404。期間が編集不可 → E2602。ABSENT → E2603。
   2. 削除。公開済みならお知らせ（本文＝N1004。時間指定なら枠名に N1006）。操作ログ `ASSIGNMENT_REMOVE`。
2. `redirect:/manager/periods/{id}`、フラッシュ I2607。

### 3.6 公開（POST /manager/periods/{id}/publish）

1. `AssignmentService#publish(periodId, operatorId)`（`@Transactional`）
   1. 期間がない → 404。status が CLOSED でない →【エラー】E2610
   2. `ShiftWarningService#calculate(period)` に TRAINEE_ONLY がある →【エラー】E2611（引数：件数）
   3. status＝PUBLISHED、`published_at`＝今。
   4. 有効なバイト全員に PUBLISHED のお知らせ（件名 N0002、本文 N1002「{M/d〜M/d} のシフトが公開されました。」、link_url `/staff/shifts?periodId={id}`）。
   5. 操作ログ `SHIFT_PUBLISH`（target：`period:{id}`、detail：`2026-11-01〜2026-11-15 assignments={割当数}`）。
2. `redirect:/manager/periods/{id}`、フラッシュ I2608。人数不足・職能不足・無効なスタッフの割当が残っていたら W2606 も出す（公開はする）。

## 4. 警告の計算（ShiftWarningService#calculate）

```
for 期間の日 d（昇順）:
  for 枠 s（id 昇順）:
    A = その日の ASSIGNED の割当のうち、(slot_id = s.id) または (slot_id IS NULL かつ 時間が s と重なる)
    count = A の件数
    required = requiredCounts[d][s.id]
    if count >= 1 かつ A の全員が研修中:  TRAINEE_ONLY（W2603：日付, 枠名）
    if count < required:                  SHORTAGE（W2601：日付, 枠名, count, required）
    for a in A（氏名のふりがな順）:
      if a.user の職能が s の必要職能をすべて含まない:  SKILL（W2602：日付, 枠名, 氏名）
    for a in A（氏名のふりがな順）:
      if d >= today かつ a.user が無効（is_active = FALSE）:  INACTIVE_STAFF（W2607：日付, 枠名, 氏名）
並び：日付 → 枠 → 種類（TRAINEE_ONLY, SHORTAGE, SKILL, INACTIVE_STAFF）の順
```

- 無効なスタッフは出勤しないので、店長が割当を外すまで警告を出します。人数（count）には数えたままにします（割当を外すと人数が減り、SHORTAGE が出る）。今日より前の日は、すでに働いた日なので警告しません。`today` は `LocalDate.now(clock)`。公開は止めません（W2606 の対象にはなる）。

- 「重なる」は `ShiftTimeUtil#overlaps(aStart, aEnd, bStart, bEnd)` ＝ `aStart < bEnd && bStart < aEnd`（終わりと始まりが同じ時刻は重ならない）。
- `countFor(date, slot)`（SM-01で使う）は上の count と同じ数え方。
