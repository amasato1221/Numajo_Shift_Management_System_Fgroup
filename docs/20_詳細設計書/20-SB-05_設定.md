### 1.3 登録のしかた（画面にそのまま書く文）

- **Googleカレンダー：** パソコンで Googleカレンダーを開き、「他のカレンダー」の「＋」→「URLで追加」に購読用URLを貼り付けます。※ このシステムをインターネットに公開していない間は、Googleカレンダーには反映されません。
- **Appleのカレンダー（iPhone・Mac）：** 上の「iPhone・Macで開く」を押し、「照会」（購読）を選びます。iPhoneでは「設定」→「カレンダー」→「アカウント」→「アカウントを追加」→「その他」→「照会するカレンダーを追加」に購読用URLを入れても登録できます。
- **TimeTree：** TimeTreeのアプリで、上で登録したGoogleカレンダーかiPhoneのカレンダーを表示する設定にします。
- 反映されるまでの時間は、カレンダーアプリによって数分〜1日かかります。

## 2. 処理

### 2.1 初期表示（GET /staff/settings）

1. `NotificationSettingService#findDays(userId)`：`notification_settings` の `days_before` を昇順で取り、`NotificationSettingForm.daysBefore` に入れる。
2. `CalendarFeedService#getOrCreate(userId)`：`calendar_feeds` の行を返す。なければ作る（`TokenGenerator#generate()`）。
3. `feedUrl`、`webcalUrl` を作る（`CalendarFeedService#feedUrl(token)`、`#webcalUrl(token)`）。
4. model：`notificationSettingForm`、`dayOptions`（`[0,1,3,7]` と表示名）、`feedUrl`、`webcalUrl`。`staff/settings` を返す。

### 2.2 締切通知の保存（POST /staff/settings/notifications）

1. `daysBefore` が null なら空のリストにする（全部外したとき）。
2. `NotificationSettingService#save(userId, daysBefore)`（`@Transactional`）
   1. 0・1・3・7 以外の値がある →【エラー】E1501
   2. 重複を取り除く。
   3. `NotificationSettingRepository#deleteByUserId(userId)` のあと、値ごとに1行入れる。
3. `redirect:/staff/settings`、フラッシュ I1501（0件のときは W1501「締切通知は届きません。」も出す）。

### 2.3 購読URLの再発行（POST /staff/settings/calendar/reissue）

1. `CalendarFeedService#reissue(userId)`：`token` を新しい値にし、`created_at` を今にする（行がなければ作る）。古いURLは使えなくなる。
2. `redirect:/staff/settings`、フラッシュ I1502。

### 2.4 トークンの作り方（TokenGenerator#generate）

- `SecureRandom` で32バイト作り、`Base64.getUrlEncoder().withoutPadding()` で文字列にする（必ず43文字、`A-Z a-z 0-9 - _`）。
- `calendar_feeds.token` の一意制約に引っかかったら、作り直す（最大3回。それでもだめなら例外）。
