# 設計書の目次

シフト管理システムの設計書です。対象読者は実装をする班員で、**誰が作っても同じものができる**ように書いています。設計書に書いていないことは実装で決めず、新井に確認してから設計書を直します（[92_Git運用規約](92_Git運用規約.md) 6章）。

| 項目 | 内容 |
| --- | --- |
| 版 | 第1.0版（令和8年10月21日） |
| 作成者 | 新井 |
| 元にした資料 | 01_仕様書 第1.2版、02_業務フロー、03_画面遷移図、04_画面レイアウト、05_DB設計（このリポジトリには入っていません） |

## 番号の付け方

| 番号 | 種類 |
| --- | --- |
| 10 | 基本設計書 |
| 20-xx-nn | 詳細設計書（画面IDごと。SC＝共通、SB＝バイト、SM＝店長、SA＝管理者、IC＝外部カレンダー） |
| 30-nn | クラス設計書（パッケージごと） |
| 40 | DB設計書 |
| 91〜98 | その他の設計書（規約・メッセージ・セキュリティ・定期処理・環境構築・テスト・実装計画） |

ファイル名は `番号_名前.md` です。番号を変えるとほかの文書からの参照が切れるので、番号は変えません。文書を足すときは空いている番号を使います。

## 読む順番

1. [96_環境構築手順書](96_環境構築手順書.md) でPCを準備し、[98_実装計画書](98_実装計画書.md) 3章の確認スクリプトで合格を確かめる
2. [10_基本設計書](10_基本設計書.md)、[91_コーディング規約](91_コーディング規約.md)、[92_Git運用規約](92_Git運用規約.md) を読む
3. 担当する部分の 20（画面）・30（クラス）・40（DB）を読む
4. テストは [97_テスト計画書](97_テスト計画書.md) の基準で書く
