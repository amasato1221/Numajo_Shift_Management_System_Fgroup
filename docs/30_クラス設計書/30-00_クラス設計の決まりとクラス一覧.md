## 1. この設計書の読み方

30_クラス設計書は、作るクラスを**全部**、パッケージごとに書いたものです。ここにないクラスは作りません。必要になったら、先に設計書を直してから作ります。

| 文書 | 中身 | コードの載せ方 |
| --- | --- | --- |
| 30-00（この文書） | 決まり、クラスの一覧 | なし |
| 30-01 | 起動クラス、config、constant | **全文**（そのまま写す） |
| 30-02 | entity（17クラス＋複合主キー4クラス） | **全文**（そのまま写す） |
| 30-03 | repository（17インターフェース） | **全文**（そのまま写す） |
| 30-04 | security（ログイン・権限） | **全文**（そのまま写す） |
| 30-05 | service | メソッドの一覧と処理の要点（手順は 20_詳細設計書） |
| 30-06 | controller、ControllerAdvice | URLとメソッドの一覧 |
| 30-07 | form、dto | 項目と入力チェックの一覧 |
| 30-08 | exception、util、scheduler | util は**全文**、ほかは一覧 |

「全文」の部分は、検証用のプロジェクトで実際にコンパイルし、テスト（75件）がすべて通ることを確かめたコードです（令和8年10月21日、JDK 21＋MariaDB で確認。本番の JDK 22・MySQL 8.4 でも同じ書き方で動きます）。1文字も変えずに写してください。

第1.1版（令和8年10月22日）で直したコード（`PeriodStatus`・`NotificationType`・`SubmissionState`・`WarningType`、`ShiftAssignmentRepository#countAssignedFrom`、`LoginFailureHandler`、`DateTimeUtil`・`GlobalExceptionHandler`）は、直した部分を単体テストで確かめました（各文書の改版履歴）。`countAssignedFrom` の JPQL は DB を使うテスト（`RepositoryQueryTests`）で、実装のときに確かめます。

**コードと説明が食い違っていたら：** 「全文」のコードと、20_詳細設計書・94 などの説明文が違っているのを見つけたら、実装を止めて新井に連絡します。新井がどちらを正しくするか決め、両方を同じ内容に直してから実装を続けます（92_Git運用規約 6章）。自分の判断でどちらかに合わせてはいけません。

## 2. クラスを書くときの決まり

| 項目 | 決まり |
| --- | --- |
| 命名 | クラスは UpperCamelCase、メソッド・変数は lowerCamelCase、定数は UPPER_SNAKE_CASE（業界標準。91_コーディング規約 2章） |
| 依存の受け取り | コンストラクター注入だけ。`private final` のフィールド＋ Lombok の `@RequiredArgsConstructor`。`@Autowired` をフィールドに付けてはいけない |
| Lombok | 使ってよいのは `@Getter`、`@Setter`（entity・form だけ）、`@RequiredArgsConstructor`、`@NoArgsConstructor`、`@AllArgsConstructor`（複合主キーだけ）、`@EqualsAndHashCode`（複合主キーだけ）、`@Slf4j`。`@Data` と `@Builder` は使わない |
| DTO | Java の `record` にする（30-07） |
| トランザクション | Service のクラスに `@Transactional(readOnly = true)` を付け、更新するメソッドだけに `@Transactional` を付け直す |
| 日時 | `Clock` を受け取り `LocalDateTime.now(clock)`・`LocalDate.now(clock)` を使う |
| コメント | クラスと public メソッドに日本語の Javadoc（`/** … */`）を1行以上書く |
| null | Service の戻り値で「ないかもしれない」ものは `Optional` にする。コレクションは null を返さず空にする |

## 4. 依存の向き

```
controller ──▶ service ──▶ repository ──▶ entity
    │             │  └──▶ util
    ├──▶ form     └──▶ dto（作って返す）
    └──▶ dto（受け取って画面へ）
scheduler ──▶ service
security ──▶ repository、service（OperationLogService だけ）
```

- 矢印の逆向き（例：service が controller や form のクラスを import する）はしてはいけません。ただし次の例外だけ認めます：(1) `ShiftRequestService`・`StaffService`・`ManagerAccountService`・`OperationLogService`（`search`）は form を引数に受け取る（項目が多く、値を1つずつ渡すと間違えやすいため）。(2) 編集画面の初期値を作る `ShiftRequestService#toForm`・`StaffService#getForEdit`・`SkillService#getSlotSkillForm`・`RequiredStaffService#getDefaultForm` は form を作って返す。受け取った form は Service の中で読むだけにし、`BeanUtils.copyProperties` で entity にコピーしてはいけません。
