## 1. この規約の考え方

- 命名と書き方は、業界で広く使われている標準（Oracle の Java コード規約、Google Java Style Guide、Spring の公式ドキュメントの書き方）に従います。この文書は、その中で**迷いやすいところと、このチームで決めたこと**を書きます。
- 開発には **Eclipse だけ**を使います（VS Code の使用は禁止）。書式は Eclipse のフォーマッター（6章の設定）でそろえます。
- 30_クラス設計書に「全文」として載せているコードは、この規約に合わせて書いてあります。迷ったら、そのコードの書き方をまねしてください。

## 2. 命名

### 2.1 Java

| 対象 | 形 | 例 | 決まり |
| --- | --- | --- | --- |
| パッケージ | 小文字のみ | `jp.numajo.fgroup.shift.service` | 単語をつなげない。区切りが必要なら下の階層にする |
| クラス・インターフェース・enum・record | UpperCamelCase（名詞） | `ShiftAssignment`、`PeriodStatus` | 略語も先頭だけ大文字（`IcsUtil`、`HtmlUtil`。`ICSUtil` にしない） |
| メソッド | lowerCamelCase（動詞から始める） | `findByLoginId`、`createUpcomingPeriods` | 真偽値を返すものは `is`／`has`／`can`／`exists` で始める |
| 変数・引数・フィールド | lowerCamelCase（名詞） | `periodId`、`workDate` | 1文字の名前は `for` のカウンター（`i`、`j`）とラムダの引数だけ |
| 定数（`static final`） | UPPER_SNAKE_CASE | `MAX_FAILED_COUNT`、`PAGE_SIZE` | |
| enum の値 | UPPER_SNAKE_CASE | `TRAINEE_ONLY` | DBの値と同じ綴りにする |
| 型パラメーター | 大文字1文字 | `T` | |
| テストクラス | 対象クラス名＋`Tests` | `ShiftRequestServiceTests` | Spring Boot の書き方に合わせて複数形の `Tests` |
| テストメソッド | 日本語で `条件_期待する結果` の形（JUnit は日本語のメソッド名を使える） | `期限を過ぎて提出_E1303になる` | 何を確かめるかが名前だけで分かるようにする。`@DisplayName` は付けない（97_テスト計画書 3.3） |

### 2.2 役割ごとのクラス名の付け方

| 役割 | 付け方 | 例 |
| --- | --- | --- |
| コントローラー | 利用者の種類＋対象＋`Controller` | `StaffRequestController`、`ManagerPeriodController`、`AdminLogController`（例外：共通の画面は `LoginController`・`NoticeController` のように対象＋`Controller`） |
| サービス | 対象＋`Service` | `ShiftRequestService` |
| リポジトリ | エンティティ名＋`Repository` | `ShiftAssignmentRepository` |
| エンティティ | テーブル名の単数形を UpperCamelCase | `shift_assignments` → `ShiftAssignment` |
| 複合主キー | エンティティ名＋`Id`（`entity.id` パッケージ） | `RequestSubmissionId` |
| フォーム | 画面の操作＋`Form` | `ShiftRequestForm`、`StaffSearchForm` |
| 表示用 DTO（record） | 内容＋`Row`（一覧の1行）／`View`（1画面分）／`Option`（プルダウンの選択肢）／`Result`（処理結果） | `NoticeRow`、`DashboardView`、`PeriodOption`、`BackupResult` |
| 例外 | 内容＋`Exception` | `BusinessException` |
| 定期処理 | 内容＋`Scheduler` | `PeriodScheduler` |
| 共通処理 | 内容＋`Util`（`static` メソッドだけ）、内容＋`Generator`／`Runner`（Bean） | `DateTimeUtil`、`TokenGenerator`、`ProcessRunner` |

クラス名は 30_クラス設計書の一覧にあるものだけを使います。新しいクラスが必要になったら、先に設計書を直します（92_Git運用規約 6章）。

### 2.3 リポジトリのメソッド名

Spring Data JPA の「メソッド名からクエリを作る」決まり（`findBy…`、`existsBy…`、`countBy…`、`deleteBy…`、`OrderBy…Asc/Desc`、`Top3`）に従います。`@Query` を書いたメソッドは、名前の意味が分かるように付けます（例：`findUnsubmitted`、`findLatest50`）。名前と中身は 30-03 に全文があるので、そのまま写します。

### 2.4 DB

| 対象 | 形 | 例 |
| --- | --- | --- |
| テーブル | snake_case の複数形 | `shift_assignments` |
| 列 | snake_case | `work_date`、`created_at` |
| 主キー | `id`（複合主キーは列の組み合わせ） | |
| 外部キーの列 | 相手テーブルの単数形＋`_id` | `user_id`、`period_id` |
| 真偽値の列 | `is_` を付けずに形容詞・状態 | `active`、`trainee`、`must_change_password` |
| 日時の列 | `_at`、日付は `_date` | `published_at`、`work_date` |
| インデックス・一意制約 | `idx_`／`uq_` ＋ テーブルの略称（＋目的） | `idx_assign_date`、`uq_request` |
| 外部キー・CHECK 制約 | 名前を付けない（MySQL が自動で付ける） | |

### 2.5 URL・テンプレート・CSS・JavaScript

| 対象 | 形 | 例 |
| --- | --- | --- |
| URL | 小文字、単語は `-` でつなぐ、一覧は複数形（`staff` のように数えない名詞はそのまま） | `/manager/periods`、`/staff/all-shifts` |
| URL のパラメーター | lowerCamelCase | `?periodId=3` |
| テンプレートのファイル | 小文字、単語は `-`（`kebab-case`） | `manager/staff-form.html`、`staff/all-shifts.html` |
| フォームの `name` | フォームクラスのフィールド名と同じ（lowerCamelCase） | `name="newPassword"` |
| CSS のクラス | kebab-case。Bootstrap と同じ名前にしない | `badge-day`、`badge-time` |
| `data-` 属性 | kebab-case | `data-confirm`、`data-print` |
| JavaScript の関数・変数 | lowerCamelCase、定数は UPPER_SNAKE_CASE | `copyToClipboard` |

URL とテンプレート名は 10_基本設計書 付録A・3.2 にあるものだけを使います。

### 2.6 メッセージコード

`E`（エラー）・`W`（警告）・`I`（情報）・`C`（確認ダイアログ）・`N`（お知らせ）＋4けた。上2けたが画面（例：`13` ＝ SB-03）、下2けたが連番です。一覧は 93_メッセージ一覧。新しいコードは 93 に足してから使います。

## 3. Java の書き方

### 3.1 ファイルの並び

1つのファイルの中は、次の順に書きます。

1. `package`
2. `import`（4章の順）
3. クラスの Javadoc
4. アノテーション（`@Slf4j` → `@Component`/`@Service` など → `@RequiredArgsConstructor` → その他）
5. クラスの中：定数（`public static final` → `static final` → `private static final`） → フィールド → コンストラクター（Lombok を使うときは書かない） → public メソッド → private メソッド

### 3.2 書式

| 項目 | 決まり |
| --- | --- |
| 字下げ | 半角スペース4つ（タブは使わない） |
| 1行の長さ | 120文字まで |
| 中かっこ | 行の終わりに `{` を書く（K&R スタイル）。`if`・`for` の中身が1行でも必ず `{}` を付ける |
| 空行 | メソッドとメソッドの間に1行。メソッドの中で処理の区切りに1行 |
| 文字コード・改行 | UTF-8、改行は CRLF でも LF でもよい（Git がそろえる。92_Git運用規約 1.3） |
| ワイルドカード import | 使わない（`import java.util.*;` は禁止） |
| 使っていない import・変数 | 残さない（Eclipse の「インポートの編成」 Ctrl+Shift+O） |

### 3.3 コメント

- コメントはすべて**日本語**で書きます。
- クラスと public メソッドには Javadoc（`/** … */`）を1行以上書きます。引数や戻り値が名前だけで分からないときは `@param`・`@return` も書きます。
- フィールドには `/** 〜 */` で1行の説明を書きます（entity は列の意味）。
- 処理の中のコメントは「なぜそうするか」を書きます。コードを読めば分かること（「iを1増やす」）は書きません。
- 設計書の番号を書くとよい場面：業務ルールの根拠（例：`// 10_基本設計書 6.1：期限は状態だけでなく日時でも確認する`）。
- `TODO` を残したままマージしてはいけません。

### 3.4 Spring の書き方

| 項目 | 決まり |
| --- | --- |
| 依存の受け取り | `private final` フィールド＋`@RequiredArgsConstructor`。`@Autowired` は使わない |
| トランザクション | Service のクラスに `@Transactional(readOnly = true)`、更新するメソッドだけに `@Transactional`。Controller・Repository に付けない |
| 入力チェック | Form に Bean Validation（`@NotBlank` など）。コントローラーの引数に `@Validated` と、その直後に `BindingResult` |
| 画面へ値を渡す | `Model#addAttribute("名前", 値)`。名前は 20_詳細設計書の「表示元」と同じ |
| リダイレクト | `return "redirect:/…";`。フラッシュメッセージは `RedirectAttributes#addFlashAttribute("successMessage", "I1302")` |
| 現在日時 | `LocalDateTime.now(clock)`。`LocalDateTime.now()`・`new Date()`・`System.currentTimeMillis()` は禁止 |
| ログ | `@Slf4j` の `log`。`System.out.println` と `e.printStackTrace()` は禁止 |
| ログの書き方 | `log.info("BT-01 募集期間を{}件作成しました", count);` のように `{}` を使う。文字列を `+` でつながない。パスワード・トークンはログに出さない |

### 3.5 Java の文法

| 項目 | 決まり |
| --- | --- |
| `var` | 右辺で型がはっきり分かるとき（`new`、ファクトリーメソッド）だけ使ってよい |
| `Optional` | 戻り値だけに使う。フィールド・引数には使わない。`get()` を直接呼ばず、`orElseThrow(...)` などを使う |
| null | コレクションは null を返さず `List.of()` を返す。引数の null チェックは Service の入口で行う |
| 文字列の比較 | `"定数".equals(変数)` か `Objects.equals`。`==` で比べない |
| enum の比較 | `==` で比べる |
| 日付 | `java.time`（`LocalDate`、`LocalDateTime`、`LocalTime`）だけを使う。`java.util.Date`・`Calendar` は使わない |
| 例外 | `catch (Exception e)` で握りつぶさない。業務エラーは `BusinessException("E1303")`、見つからないは `ResourceNotFoundException` |
| マジックナンバー | 意味のある数字は定数にする（例：`PAGE_SIZE = 50`）。ただし設計書で決まった枠のID は `SlotIds.DAY` を使う |
| Stream | 読みやすいときだけ使う。3段より長くなるなら `for` 文で書いてよい |
| `record` | DTO は `record`。中に業務ロジックを書かない（表示用の簡単な計算は可） |

### 3.6 JPA の書き方

| 項目 | 決まり |
| --- | --- |
| 関連の取り方 | `@ManyToOne(fetch = FetchType.LAZY)` を基本にする。一覧で使うときは `JOIN FETCH` のクエリを使う（30-03） |
| `open-in-view` | `false`（10_基本設計書 8章）。テンプレートで LAZY の関連をたどらないよう、Service で DTO にしてから返す |
| JPQL の LIKE | `LikeUtil.escape` でエスケープし、`ESCAPE '!'` を付ける |
| 並び順 | null が来る列は `NULLS LAST` を付ける |
| 一括更新・削除 | `@Modifying(flushAutomatically = true, clearAutomatically = true)` を付ける（30-03 のとおり） |
| SQL を文字列でつなぐ | 禁止（SQL インジェクション対策。94_セキュリティ設計書 3.3） |

## 4. import の順番

Eclipse の「インポートの編成」の設定（6章）で、次の順にそろえます。グループの間は空行1行。

1. `java.*`
2. `javax.*`
3. `org.*`
4. `com.*`
5. その他（`jakarta.*`、`jp.*`、`lombok.*` などのアルファベット順）

`static import` は使いません（テストの `Assertions.*`・`Mockito.*`・`MockMvcRequestBuilders.*`・`MockMvcResultMatchers.*` だけ例外）。

## 5. テンプレート（Thymeleaf）・CSS・JavaScript

### 5.1 Thymeleaf

| 項目 | 決まり |
| --- | --- |
| レイアウト | `layout:decorate="~{layout/base}"`（ヘッダーなしの画面は `layout/plain`） |
| 文字の出力 | `th:text` を使う。`th:utext` は禁止（XSS 対策。94_セキュリティ設計書 3.2） |
| メッセージ | `#{E1303}` のように 93 のコードを書く。日本語の文をテンプレートに直接書くのは、見出し・項目名・ボタン名だけ |
| リンク・フォーム | `th:href="@{/…}"`、`th:action="@{/…}"`（CSRF トークンが自動で入る） |
| 日付の表示 | `${#temporals.format(d, 'M月d日(E)')}` は使わず、Service で `DateTimeUtil` を使って作った文字列を渡す（形式をそろえるため） |
| 条件 | `th:if`／`th:unless`。複雑な条件はコントローラーかサービスで真偽値にしてから渡す |
| 字下げ | 半角スペース4つ |
| インラインの `<script>`・`<style>`・`onclick` | 書かない（`app.js`・`app.css` に書く。例外は `logo.png` の `onerror` だけ） |

### 5.2 CSS

- 自分で書く CSS は `static/css/app.css` の1ファイルだけ。Bootstrap のクラスで足りるところは Bootstrap を使います。
- 色はファイルの先頭の `:root` に変数（`--color-day: #00843D;` など、20-00 4章の色）として書き、そこから使います。
- `!important` は使いません（印刷用 `@media print` の中だけ例外）。

### 5.3 JavaScript

- `static/js/app.js` の1ファイルだけ（10_基本設計書 5.2）。`'use strict';` を先頭に書きます。
- `var` は使わず `const`／`let`。イベントは `document.addEventListener('DOMContentLoaded', …)` の中で `data-` 属性を目印に付けます。
- `fetch`・`XMLHttpRequest`（Ajax）は使いません。

## 6. Eclipse の設定（全員同じにする）

「ウィンドウ」→「設定」で次のように設定します（詳しい手順は 96_環境構築手順書 4章）。

| 設定の場所 | 項目 | 値 |
| --- | --- | --- |
| 一般 → ワークスペース | テキスト・ファイルのエンコード | UTF-8 |
| 一般 → コンテンツ・タイプ → テキスト → Java プロパティー・ファイル | デフォルト・エンコード | UTF-8（`messages.properties` の日本語を文字化けさせないため） |
| Java → コード・スタイル → フォーマッター | プロファイル | 「Eclipse [組み込み]」を元に、字下げ「スペースのみ」4、行の幅 120 にしたものを `numajo-fgroup` という名前で保存 |
| Java → コード・スタイル → インポートの編成 | グループの順番 | `java`、`javax`、`org`、`com`、`*`（4章） |
| Java → エディター → 保存アクション | 保存時に実行 | 「ソース・コードのフォーマット（編集した行のみ）」「インポートの編成」をオン |
| Java → コンパイラー | 準拠レベル | 22 |
| Web → HTML ファイル → エディター | 字下げ | スペース、4 |

フォーマッターの設定は、エクスポートしてリポジトリには入れません（各自のPCで同じ値にします）。

## 7. してはいけないことの一覧

レビューでは、まずこの表を確かめます（92_Git運用規約 5章）。

| No. | してはいけないこと | 代わりに |
| --- | --- | --- |

| 14 | `System.out.println`・`printStackTrace` | `log` |
| 15 | GET で更新処理をする | POST ＋ PRG |
