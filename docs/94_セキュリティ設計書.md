## 1. この文書で決めること

## 2. 認証（ログイン）

### 2.1 方式

- **ログインIDとパスワードだけ**で認証します（Spring Security の `formLogin`）。パスキー（WebAuthn）は使いません（5章）。
- ログインの画面と流れは 20-SC-01、設定は 30-04 の `SecurityConfig`。
- ログインIDは半角英数字の4〜20文字（`^[A-Za-z0-9]{4,20}$`。20-SM-03・20-SA-02 の入力チェック）。DB の照合順序が `utf8mb4_0900_ai_ci` のため、ID は**大文字・小文字を区別しません**（`ADMIN` でも `admin` でログインでき、`Admin` と `admin` を別の人に登録することもできない。40_DB設計書）。

### 2.2 パスワードの保存

| 項目 | 決まり |
| --- | --- |
| 方式 | BCrypt（`BCryptPasswordEncoder`、強さは既定の 10） |
| 保存する列 | `users.password_hash`（60文字） |
| 平文 | DB・ログ・操作ログ・画面のどこにも残さない。初期パスワードだけは、作った直後の画面に1回だけ出す（20-SM-03・20-SA-02。フラッシュ属性で渡し、再表示すると消える） |

### 2.3 失敗回数とロック

| 項目 | 値 | 定数 |
| --- | --- | --- |
| ロックするまでの連続失敗回数 | 5回 | `LoginAttemptService.MAX_FAILED_COUNT` |
| ロックの時間 | 15分 | `LoginAttemptService.LOCK_MINUTES` |
| ロック中の動き | 正しいパスワードでもログインできない。メッセージ E0102 | |
| 解除 | `locked_until` の時刻を過ぎたら自動で解除。ちょうどその時刻からログインできる | |
| 失敗回数を0に戻すとき | ログインに成功したとき、ロックしたとき、パスワードを初期化したとき | |
| 存在しない ID | 回数は数えない（数える行がない）。メッセージは E0101（IDがあるかどうかを教えない） | |
| 無効なアカウント | メッセージは E0101（同じ理由） | |

ロック中かどうかは `LoginUserDetailsService` が `Clock` を使って計算し、`LoginUser(user, locked)` に入れます（テストで時刻を固定できるようにするため）。

### 2.4 パスワードの決まり（パスワードポリシー）

| 項目 | 決まり | どこで確かめるか |
| --- | --- | --- |
| 使える文字 | 半角の英字・数字・記号（ASCII の `!`〜`~`）。空白・全角は使えない | SC-03 の `@Pattern(regexp="^[\\x21-\\x7E]{8,64}$")`（E0303） |
| 長さ | 8〜64文字 | 同上 |
| 今と同じパスワード | 使えない | SC-03（E0307） |
| 英字と数字の組み合わせ | 強制しない（長さで強さを確保する考え方。NIST SP 800-63B と同じ） | － |
| 有効期限 | なし（定期的な変更は強制しない。NIST SP 800-63B と同じ） | － |
| 初期パスワード | `PasswordGenerator` が作る10文字（英字と数字を両方含む。見まちがえやすい `I`・`O`・`l`・`0`・`1` を使わない）。`SecureRandom` を使う | 30-08 |
| 初回ログイン | `must_change_password = TRUE` の人は、変更するまで SC-03 以外の画面を開けない（`PasswordChangeRequiredFilter`） | 30-04 |
| 初期管理者 | ログインID `admin`。初期パスワードは班の中だけで共有し、リポジトリには書かない（3.10）。**初回ログインで必ず変える**。初回ログインは、ファイアウォールでほかの端末からの接続を許可する前に、そのPC上で行う | 96_環境構築手順書 6.4 |

**注意（今後の展望）：** 「よく使われるパスワード（`password123` など）の一覧と照らし合わせて断る」機能は、今回は作りません。課題期間中は、初期管理者と店長に「推測されにくいパスワードにする」ことを口頭で伝えます。

### 2.5 パスワードを忘れたとき

メールを使わないため、自分で再設定する機能はありません。

| 忘れた人 | 初期化する人 | 画面 |
| --- | --- | --- |
| バイト | 店長 | SM-03「パスワードを初期化」 |
| 店長 | 管理者 | SA-02「パスワードを初期化」 |
| 管理者 | 新井が DB を直接更新する（96_環境構築手順書 8章） | － |

初期化すると、新しい初期パスワードを1回だけ表示し、`must_change_password = TRUE`、`failed_login_count = 0`、`locked_until = NULL` にします。

## 3. 対策

### 3.1 認可（だれがどの画面を使えるか）

| URL | 使える人 | 設定 |
| --- | --- | --- |
| `/login`、`/css/**`、`/js/**`、`/images/**`、`/webjars/**`、`/error` | だれでも | `permitAll()` |
| `/ical/**` | だれでも（トークンで守る。3.8） | `permitAll()` |
| `/admin/**` | 管理者（ADMIN） | `hasRole("ADMIN")` |
| `/manager/**` | 店長（MANAGER） | `hasRole("MANAGER")` |
| `/staff/**` | バイト（STAFF） | `hasRole("STAFF")` |
| それ以外（`/`、`/notices`、`/account/**`） | ログインしている人全員 | `authenticated()` |

- 1人は1つの役割だけを持ちます（`users.role`）。管理者が店長の画面を使うことはできません。
- 権限のない URL を開いたときは、403 画面を出さずに自分のホームへ戻します（`HomeRedirectAccessDeniedHandler`）。
- **URL だけでなく、データの持ち主も確かめます。** 次のものは、ログイン中の人の ID を条件に入れて探します（他人の ID を URL に入れても見えない）。

| データ | 確かめ方 | 見つからないとき |
| --- | --- | --- |
| お知らせ | `findByIdAndUserId(id, loginUserId)` | 404 |
| 自分のシフト・希望・設定・チャット | URL に人の ID を入れず、ログイン中の人の ID だけで探す | － |
| 店長が見るスタッフ | `role = STAFF` のユーザーだけ（店長・管理者の ID を入れても 404） | 404 |
| 管理者が見る店長 | `role = MANAGER` のユーザーだけ | 404 |

### 3.2 XSS（クロスサイトスクリプティング）

- テンプレートでは `th:text`（自動でエスケープする）だけを使い、`th:utext` は使いません（91_コーディング規約 5.1）。
- チャットの改行は、`white-space: pre-wrap`（CSS）で表示し、`<br>` に置き換えません。
- `th:href` に利用者の入力をそのまま入れません。お知らせの移動先は 3.7 の決まりで確かめます。
- JavaScript の中に利用者の入力を埋め込みません（インラインの `<script>` を書かない）。

### 3.3 SQL インジェクション

- DB へのアクセスは Spring Data JPA だけです。JPQL は `@Query` に固定の文字列で書き、値は `@Param` で渡します。文字列をつなげて SQL を作ってはいけません。
- LIKE で探すとき（スタッフ一覧の氏名検索）は、`%`・`_`・`!` を `LikeUtil.escape` でエスケープし、`ESCAPE '!'` を付けます（入力した `%` が「何でも」にならないようにするため）。

### 3.4 CSRF

- Spring Security の CSRF 対策を有効のままにします（`csrf().disable()` を書かない）。
- フォームは `th:action` で書き、トークンを自動で入れます。トークンのない POST は 403 になります。
- 更新は POST だけで行い、GET では DB を変えません（ログアウトも POST）。
- `/ical/**` は GET だけなので CSRF の対象外です。

### 3.5 セッション

| 項目 | 決まり |
| --- | --- |
| 有効時間 | 最後の操作から30分（`server.servlet.session.timeout: 30m`） |
| 切れたあと | `/login?expired` へ移動し W0101 を出す |
| ログイン時 | セッション ID を新しくする（Spring Security の既定。セッション固定攻撃の対策） |
| ログアウト時 | セッションを破棄し、`JSESSIONID` の Cookie を消す |
| Cookie | `HttpOnly`（Tomcat の既定）。課題期間中は HTTP で動かすため `Secure` は付けない（今後の展望で HTTPS にしたら付ける） |

### 3.6 ログイン中に無効にされたアカウントの締め出し

店長がバイトを「無効」にしても、すでにログインしているセッションは残ります。そのままだと画面を使い続けられるため、`UserActiveCheckFilter` で毎回確かめます。

1. ログインしている人のリクエストごとに、`UserRepository#findActiveById(userId)` で `is_active` を読み直す（静的ファイルも含め、ログイン中のリクエストすべて。1回の主キー検索なので軽い）。
2. いない、または `is_active = FALSE` なら、セッションを破棄し、`/login?disabled` へリダイレクトする（W0102 を出す）。
3. 未ログインのリクエストは何もしない。

このフィルターは `@Component` にせず、`SecurityConfig` の中で `new` します（2回動かないようにするため。30-04 0.1）。順番は `UserActiveCheckFilter` → `PasswordChangeRequiredFilter` → `AuthorizationFilter` です。

### 3.7 オープンリダイレクトの防止

お知らせを開いたときの移動先（`notifications.link_url`）は、アプリの中のパスだけにします（20-SC-02 2.2）。

- null、`/` で始まらない、`//` で始まる → `/notices` へ移動する。
- ログイン後の移動先は、役割で決まる固定の URL（`HomeUrl.of(role)`）か `/account/password` だけです。「ログイン前に開こうとした URL」へは戻しません。

### 3.8 カレンダー購読 URL のトークン

| 項目 | 決まり |
| --- | --- |
| 作り方 | `SecureRandom` の32バイトを Base64URL（`=` なし）にした43文字（`TokenGenerator`） |
| 形の確認 | `^[A-Za-z0-9_-]{43}$` に合わなければ、DB を見ずに 404 |
| 合わないトークン・無効なアカウントのトークン | 404（あるかないかを教えない） |
| 漏れたとき | 本人が SB-05 で「再発行」すると、古い URL は使えなくなる |
| 中身 | 本人の公開済みの出勤（ASSIGNED）だけ。ほかの人の名前・チャットは入れない |

### 3.9 バックアップのコマンド

- `mysqldump` は `ProcessRunner` で、引数を**リスト**で渡して起動します。1本の文字列にして `cmd /c` で動かしてはいけません（コマンドインジェクション対策）。
- 引数に入るのは設定ファイルの値と、アプリが作ったファイル名（`backup_yyyyMMdd_HHmmss.sql`）だけで、利用者の入力は入りません。
- DB のパスワードは引数に入れず、環境変数 `MYSQL_PWD` で渡します（タスクマネージャーのコマンドラインに出ないようにするため）。
- バックアップのファイルは `app.backup.dir`（新井のPCの決めたフォルダ）に置き、画面からダウンロードできるようにはしません。

### 3.10 秘密情報の扱い

| 情報 | 置き場所 | リポジトリ |
| --- | --- | --- |
| DB のパスワード | 環境変数 `DB_PASSWORD`（Eclipse の「実行の構成」→「環境」） | 入れない |
| 初期管理者のパスワード | V2 の SQL に BCrypt のハッシュだけ。平文は班の中だけで共有する（`DB_PASSWORD` と同じく、文書にも書かない） | ハッシュは入れてよい（初回ログインで変えるため）。平文は設計書・コメントを含めて入れない |
| ロゴ画像 | 各自のPCの `src/main/resources/static/images/logo.png` | 入れない（`.gitignore`） |
| スタッフの個人情報 | DB だけ。テスト用のデータは架空の名前にする | 本物の名前を入れない |

### 3.11 HTTP ヘッダー

Spring Security が既定で付けるヘッダー（`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Cache-Control: no-cache, no-store`）をそのまま使い、無効にしません。

## 5. 今後の展望（今回は作らないもの）

| 項目 | 内容 | 今回作らない理由 |
| --- | --- | --- |
| パスキー（WebAuthn） | 指紋・顔認証でログインする。Spring Security 7 の `webAuthn()` で作れる | 01_仕様書 第1.2版で今後の展望に移した。パスキーは HTTPS（または localhost）が必要で、スマホから新井のPCの IP アドレスで使う課題期間中の動かし方では動かないため |
| HTTPS | 証明書を入れて暗号化する。Cookie に `Secure` を付ける | 課題期間中は学内・店内の同じネットワークだけで使うため |
| 二要素認証 | パスワード＋ワンタイムコード | 同上。メールを使わないため |
| よく使われるパスワードの拒否 | 一覧と照らし合わせる | 2.4 の注意 |
| 操作ログの保存期間 | 一定期間で消す | 課題期間が短いため |
